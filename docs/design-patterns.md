# Design patterns for the renewal — fit against refactoring.guru

Status: research note, 2026-09-06. Vocabulary follows [`CONTEXT.md`](../CONTEXT.md); seams come from the three audits (`audit-color-science.md`, `audit-components.md`, `audit-ml-feedback.md`) and `cms-data-model.md`.

> Note: this note was drafted before the 2026-09-06 decision to keep the code's existing vocabulary; terms were normalised afterwards (Preset, Processed Image, Parent Color, Feedback, Knowledge Base). Where the model "re-ranks near ties" the glossary term is **Knowledge Base**.

Source of pattern definitions: the refactoring.guru catalog (<https://refactoring.guru/design-patterns/catalog>). Every intent quote below is the page's own one-sentence "Intent" line, fetched 2026-09-06. **The catalog has no "Repository" pattern** — it lists 23 GoF patterns and Repository is not among them. Repository is a Fowler *Patterns of Enterprise Application Architecture* pattern; the closest catalog patterns for the persistence seam are Adapter (translate VAMS/Strapi wire shapes into the app's own types) and Facade (one entry point hiding the Netlify function + Spaces + CMS trio). This note uses "gateway" for that seam to avoid implying a GoF pattern.

## 2. Already present or half-attempted

**Facade — `analyzeImage`** (`services/imageAnalyzer.js:29-109`). Real and useful: one entry point over `getImageColors` + `matchColors`. Flaw: it also owns option defaulting/forcing (`:36-52`) that `useAnalysisSettings.js:12-23,50-56` repeats, and it re-emits `analysisSettings` (`:81-89`) — a third copy of the profile. **Keep**; move profile construction out.

**Ad-hoc Singleton — `useColorMatcherService`** (`composables/useColorMatcherService.js:14,21-25`). Module-level `serviceInstance`, constructed with the *hardcoded* `parentColors` from `data/colors` (`:11,25`), so it never sees user-edited parent colours. `colorMatcher.js:73-94` calls six methods (`findClosestColor`, `prepareColorFromHex`, …) that `HybridColorMatcherService.js` does not define; the `try/catch` swallows the TypeError and every match reports `"mathematical"` (audit-ml-feedback §Reachability). It also drags `@tensorflow/tfjs` into the client bundle. **Remove**; replace with a Knowledge Base value passed into the matcher.

**Strategy stub — distance method / colour space** (`colorMatcher.js:8-33`; duplicated `imageAnalyzer.js:9-12`; `imageAnalyzerSupport.js:25-28,63-69` where `convertPixelsToColorSpace` ignores its `colorSpace` argument). Forced back to LAB/ΔE at `imageAnalyzer.js:50-51` and `useAnalysisSettings.js:53-56`; rendered as two `disabled` selects in `ImageControls.vue:323-356`. Two modules import `DISTANCE_METHODS` from *different* files (`useAnalysisSettings.js:3` vs `ImageControls.vue:529`). **Remove** the switch, the constants and the disabled UI; keep ΔE₀₀ as the one distance.

**Adapter attempt — `cmsInterface` / `fileStorage`** (`services/feedback/feedbackStorage.js:55-139,142-242`, selected at `:245`). Two same-shaped objects behind one export — the right *shape* for a swappable gateway. But the CMS side returns `"not implemented"`, the file side uses `fs` + `process.cwd()` (fails on Lambda), and the audit finds the module dead with four diverged copies. **Remove** the file; reuse the idea (duck-typed gateway object) for the VAMS seam.

**Half-Memento — `originalParent`** (`useColorFeedback.js:100-102`). A snapshot of the pre-feedback `parent` is stored on the colour, but nothing in `composables/`, `components/` or `services/` reads it back — no restore path. **Finish** as a one-level "revert Feedback", or delete the field.

**Observer via Vue `watch`** (`useAnalysisSettings.js:131-144` persists; `ImageControls.vue:677-680` re-emits `updateSettings` on every deep change, *and* `handleUpdateSettings` `:646-657` emits again). Two notification channels exist: `headerRef.showNotification` (`app.vue:233-235`) and a local toast in `ImageControls.vue:659-673`. **Finish** by collapsing to one `useNotifications()` store; delete the template-ref path. Note `app.vue:179` destructures `settings` as `analysisSettings`, then `app.vue:248,266,334` read `analysisSettings.settings.value` / `.updateSettings` — both undefined on a ref, so reanalysis silently runs with `{}` and the settings toast never fires.

## 4. Recommended pattern map for the renewal

refactoring.guru's own cons are the guide here: Strategy adds complexity for "a couple of rarely-changing algorithms", Facade/Mediator "can become a god object", Singleton "can mask bad design", State "may be excessive" for few states. Prefer the smallest thing that works; most seams need a function, not a class.

1. **Matcher + Knowledge Base → Decorator (functional).** `matchParentColor(colorLab, parentColors) → ranked candidates with Distance`. Knowledge Base is `rerankNearTies(model, candidates, epsilon)`, applied only when a model is passed. Composition, no inheritance, no singleton, fully unit-testable. Not Strategy (one metric), not Chain (compose, don't short-circuit).
2. **Persistence → Adapter behind a plain module ("gateway"; Repository in Fowler's terms).** `presetGateway = { list, get, save, remove }` with a Strapi adapter today and a VAMS adapter tomorrow, chosen by one `createGateway(env)` function — no Factory Method hierarchy. The migration script is a third caller of both adapters, not a pattern.
3. **Analysis pipeline → keep the Facade, no other pattern.** `analyzeImage(source, profile, parentColors, pantoneList)` stays the single entry point; inside it is a straight-line sequence of pure functions. Keep profile construction and matching *out* of it so it does not become the god object the page warns about.
4. **Analysis Settings → no pattern — plain function.** `createAnalysisSettings(overrides = {})` merges defaults, clamps ranges, returns a frozen object. Not Builder. Delete the three duplicate default tables.
5. **Notifications / shared state → Observer via Vue, not hand-rolled.** One `useNotifications()` (or Pinia store) exposing `notify(msg, type)`; components call it directly. Remove `headerRef`/`feedbackManagerRef` method calls and the second toast. Mediator is unnecessary once state lives in a store.
6. **HybridColorMatcherService singleton → remove.** The Knowledge Base becomes a plain value (`{ version, parentColorsId, weights }`) loaded once by the caller and passed to `rerankNearTies`. Nothing global.
7. **Image loaders (File/Blob/URL) → no pattern — one function.** `toImageBitmap(source)` normalises `File | Blob | string URL` to an `ImageBitmap`; `loadPixels(bitmap, maxImageSize)` follows. Adapter in spirit, but too small to name. Delete legacy `loadImageData`.
8. **Feedback entries → Memento (one level) now; Command only if undo *history* is required.** Store the previous `Match` on the Feedback record (`{ from_family, to_family }` already in `cms-data-model.md`), expose `revertFeedback(id)`. Skip Command unless the researcher asks for multi-step undo/redo across an Analysis.

Over-patterning warning: the codebase already shows what happens when patterns are added on speculation — an inert Strategy switch, a Singleton wrapping a service that lacks its own methods, a CMS Adapter that returns "not implemented", a Memento with no restore. Add a pattern only when a second concrete implementation exists *today* (Strapi + VAMS) or the behaviour is specified in `CONTEXT.md` (Knowledge Base re-ranking). Everything else: a well-named function.
