Knowledge Base: why three attempts failed, and a path that can work

HybridColorMatcher · enhancedMatcher · pattern KB
0 feedback entries ever stored

All three attempts share one root cause: model before data. Each built inference machinery — a TensorFlow network, a genetic optimiser, a pattern store — before a single piece of human feedback could be saved, before there was a way to measure whether a match was “better”, and before the parent colours themselves were defensible. The neural network has 18 inputs and two hidden layers; it has had zero training examples.

What actually went wrong

  • No persistence — the feedback POST always 400s; the modal never posts; the training index is positional and breaks when the parent-colour list is edited.
  • No evaluation — nothing measures agreement with people, so no version could ever be shown to beat plain ΔE₀₀.
  • Wrong target — learning to “correct” matches against 32 CSS colours learns the wrongness of the list, not human perception.
  • Wrong tool for the data size — a neural net wants thousands of labelled examples; one researcher produces tens per session.
  • Two questions in one model — “which parent colour is this?” (matching) and “what mood does this painting evoke?” (research) are different datasets and different methods.

The sequence that can work (track F)

  1. Data first. Persist Feedback with the parent-colour list version, the colour's LAB, the context, and who said so.
  2. Baseline. Deterministic ΔE₀₀ against a painter's list. Measure agreement with a small panel on ~300 colours. Record it. Record inter-rater agreement too — no model should be expected to beat it.
  3. v1 — learned prototypes. Nearest-prototype matching where each parent's LAB prototype moves to the centroid of corrected examples. Dozens of parameters, interpretable, trainable on 100 entries, never invents a parent that doesn't exist.
  4. v2 — multinomial logistic regression on (L, a, b, C, h, ΔE to top-3). A few hundred parameters; still explainable per parent.
  5. v3 — only past 5 000 entries and a v2 plateau: a small MLP, trained server-side, shipped as weights, same harness.
  6. Mood is a separate study, later: ratings on images, analysed against results with ordinary statistics first. The colour-emotion literature (Ou et al.; Palmer & Schloss) gives a starting vocabulary — cite it, test it, don't assume it.

Rule: a Knowledge Base version ships only when the harness shows it beats the active version on held-out Feedback. Otherwise it is saved as a knowledge-base entry with status retired and the numbers stay in the repo. That is what turns “many fronts, none working” into learning.
